## 해결한 문제와 적용 구조

서버 사냥 응답, 로컬 지갑, 장비 옵션, 캐릭터 스탯, UI 예상치가 각자 값을 만드는 구조를 정리했다. 이번 버전의 권한은 명시적으로 `local-client`다. 기존 로그인은 유지하지만 옛 사냥·강화 응답이 새 경제 상태를 덮어쓰지 않는다.

- `Assets/_Project/Scripts/Core/Balance/BalanceMath.cs`: 비용·성장·데미지·EXP·적 수치·뽑기 확률 구간의 공통 계산. 재화·HP·데미지는 64비트, 곱셈은 decimal, 지정된 단계에서만 반올림한다.
- `LocalProgression.cs` / `ProgressionState.cs`: 계정별 스냅샷, 밸런스 버전, 권한, revision, 수령 기록. 복제본에서 비용과 보상을 계산하고 검증 → 임시 파일 flush → 파일 교체가 성공한 뒤 상태와 이벤트를 공개한다. 중복 수령, 음수 지출, 부족한 잔액, 저장 실패가 부분 반영되지 않는다.
- `BattleEconomy.cs`: 최초 스폰에서 입장권 차감, 전투 ID와 처치 순번으로 보상 확정, 최초 클리어와 해금의 영구 기록. 사망 연출 완료가 아닌 치명타 확정 시 처치를 집계한다.
- `QuestEconomy.cs` / `catalog.json`: 활성 가이드 28개, 일일 8개, 주간 7개, 업적 49개. 현재치·최고치·기간 누적치를 구분하고 초기화나 환생으로 업적 기록이 역행하지 않게 했다.
- 기존 장비·전직·마법·환생·오프라인·뽑기 매니저와 UI가 위 상태를 사용한다. 버튼 예상 비용과 실제 차감은 같은 함수를 호출한다.

## 경제 곡선 해석

| 검산 지점 | 결과 |
|---|---:|
| 골드 한 트랙 0→10 | 696 G |
| 0→50 | 20,351 G |
| 0→100 | 619,133 G |
| 0→300 | 466,665,042,390 G |
| 계정 1→200 누적 EXP | 6,129,211 |
| 마법 E0→100 누적 지식 | 12,427 |
| 보스 1 / 2 / 3 HP | 3,735 / 10,657 / 30,404 |
| 새 계정 3창병 전투력 | 1,050 |

**상한 300은 베타 3개 스테이지의 완주 목표가 아니다.** 비용은 스탯보다 빠르게 증가한다. 후반 상한을 단기간에 채우도록 재화를 부풀리면 초반·중반 보상이 의미를 잃으므로 원문의 한계를 유지했다. 장기 서비스에서 스테이지·골드 던전 확장 시 이 구간을 다시 설계해야 한다.

고정 안전 웨이브 30 KPM, 온라인 30분 + 오프라인 8시간, 루비·퀘스트 제외 가정에서 1-10 메인 수입은 하루 181,260 G이며 골드 던전1 두 회를 더하면 199,260 G다. 동일 조건의 3-10 EXP는 하루 228,960으로 계정 200까지 약 27일분이다. 이는 **도달 시점 이후의 수입 모델**이며 새 계정의 실제 완주시간이나 7일 유지율 실험 결과가 아니다. 무료 주화·파편·지식 유입은 활성 퀘스트/최초클리어와 연결해 유료 뽑기 없이 강화와 전직을 시작할 수 있게 했다.

## 보상·저장 경계와 이관

1. 안정적인 PlayFab 계정 ID(`GetSessionID`의 실제 반환은 PlayFabId)를 해시해 계정별 저장 파일을 분리한다. 토큰이나 세션 GUID를 파일명·버전 관리 파일에 저장하지 않는다.
2. 구 서버 계정·장비·마법 원본은 로컬 이관 모듈에 보존한다. 현재 베타 범위의 계정·강화 상한을 적용하고, 도달한 메인 위치보다 **엄격히 앞선** 웨이브만 해금의 근거로 복원한다. 현재 보스는 클리어로 간주하지 않으며 과거 클리어 재화는 소급 지급하지 않는다. 이미 열렸어야 할 마법의 미소유 상태만 복구한다.
3. 구 아이템 코드가 새 카탈로그에 없으면 원본과 미해결 표시를 보존한다. 가방+보관함 용량을 초과하는 대량 이관은 일부만 지급하지 않고 전투 시작을 보류한다. 구 전역 PlayerPrefs 환생은 계정 귀속을 증명할 수 없어 원본을 보존하고 자동 합산하지 않는다. 기존 마법 지출을 알 수 없으므로 초기화 환급액을 역산해서 만들어내지 않는다.
4. 장비 가방 300 / 보관함 100. 보상 공간이 부족하면 다음 전투를 보류한다. 보관 만료 시 자동 삭제는 아직 실행하지 않는다. 기존 아이템 손실을 피하기 위한 클라이언트 보존 결정이며 서버 만료 정책 이관 시 별도 검토 대상이다.
5. 처치/클리어 보상 저장 실패는 전투를 멈추고 화면에 알린다. 재접속해도 이전에 확정된 잔액·수령 기록을 유지한다. 손상된 주 저장 파일은 새 계정으로 조용히 초기화하지 않는다. 로컬 백업은 보존하되 자동 롤백으로 중복 보상을 만들지 않는다.

서버 연결 시 `IsLocalAuthority`만 뒤집어 양쪽 쓰기를 활성화하면 안 된다. 인증된 계정·권한 모드·밸런스 버전·기대 revision·명령 ID를 함께 전달하고, 서버가 가격·확률·현재 자격을 재계산한 **확정 결과와 영수증**으로 스냅샷을 교체해야 한다. 최초클리어/퀘스트/뽑기 천장/실제 지출/오프라인 기준시각/진행 중 던전/기간 키도 함께 이관한다. 이 구현은 서버 인증·부정행위 방지·다중 기기 동시 쓰기를 제공하지 않는다. KST 초기화와 오프라인 시간은 현재 기기 시계를 사용한다.

## 에셋과 수정 범위

7개 직업, 18개 장비, 마법 수치, 뽑기 테이블, 43개 스테이지를 실제 직렬화 에셋에 반영했다. 기존 프리팹·그림·GUID를 보존했다. 수치 검증용 골드 던전은 현재 로드 가능한 ORC 비주얼을 사용한다. 2스테이지의 구 Goblin에는 Animator 연결이 없어 로드 가능한 BanditShield/Archer를 임시 사용한다. 기존 고블린/오크 에셋을 삭제하거나 미믹·새 로스터 아트를 제작했다고 간주하지 않는다.

골드 강화 1/10/MAX, 장비 재료·분해·잠금, 루비 성장, 퀘스트 지급, 던전 입장권과 실제 보상을 기존 UGUI에서 조작할 수 있게 연결했다. 기존 사용자의 HUD·안내 패널 편집은 유지했다. 신규 텍스처·아틀라스는 추가하지 않았고 UI 갱신은 revision/값 변화에 따라 수행한다.

이전 `personalDocs/Stage_Revised.xlsx` 생성 메뉴는 새 43개 정의를 오래된 무한 템플릿으로 덮어쓰지 않도록 현재 베타 카탈로그가 있을 때 중단한다. 다음 수치 개정은 `BalanceMath`, 직업/장비/마법 SO, 명시적 StageDatabaseSO, 활성 퀘스트 카탈로그를 함께 검토해야 한다. 문서만 수정하면 런타임 수치가 자동 갱신되지는 않는다.

## 검증 방법과 결과 파일

- Unity 6000.3.21f1에서 import/컴파일, 직렬화 참조 검사, 계산·저장 인수 검사를 실행한다: `-batchmode -nographics -quit -executeMethod BalanceEditorValidation.Run`.
- Android 빌드: `BalanceEditorValidation.BuildAndroid`. 기존 QA 빌더를 사용하며 실앱과 다른 `.lobbyqa` 패키지/격리 계정으로 테스트한다. 테스트 훅은 `LOBBY_DEVICE_QA && DEVELOPMENT_BUILD`에서만 탑재한다.
- 계산 검사는 합산 가격 경계, 64비트/반올림, EXP 초과, 잔여 소수 이월, 보스/던전 보상, 확률 100만 구간 전수 검사, 퀘스트 최고치/중복 수령, 파일 저장 실패와 재개봉, 환생과 초기화 환급을 포함한다. 40회 저장 처리량 측정을 40개의 독립 규칙 검증으로 부풀리지 않는다.
- 세부 결과와 캡처는 `validation/`에 보존한다. 원본 로그·설치 APK·테스트 계정 파일은 무거운/기기별 산출물이므로 버전 관리 대상이 아닌 `Recordings/BalanceRevision/`에 있다.

실기기는 Samsung SM-N986N(Android 13) 한 대다. Unity Editor에서는 import·컴파일·직렬화 참조·계산 검사를, 실제 게임 실행은 이 Android 기기에서 검증했다. Editor Play Mode의 수동 플레이를 별도로 수행했다고 간주하지 않는다. 다른 해상도 검사는 이 한 기기에서 화면 비율을 변경하는 시험이며 여러 실제 기기 검증이 아니다. 7일 실사용 추적, 서버 권한 전환, 실제 태블릿/저사양 기기 테스트는 완료 범위에 넣지 않는다.

수정 과정에서 ① 장비 액션 영역에 서로 충돌하는 LayoutGroup 추가, ② 존재하지 않는 던전 ORC 주소, ③ 구 Goblin의 Animator 결손, ④ QA 검사 후 임시 계정의 스탯이 화면에 남는 문제를 발견해 수정하고 다시 빌드·실행했다. 개발용 검사 계정은 실제 플레이용 QA 계정과 분리하고 검사 종료 후 장비·마법·스탯을 복원한다.

추가 조작 검사에서 카메라 영역으로 전투 대상을 제외하면 패널 개폐 후 가장자리 원거리 적이 파티를 공격하면서도 탐지에서 빠지는 문제가 드러났다. 표적 유효성은 활성/생존 여부와 물리 탐지 범위로 판단하도록 바꿨다. 오래된 사망 이벤트가 새 표적을 해제하지 않도록 구독도 해제한다. 정예 직업에 기존 직군 무기 마스크가 맞지 않는 문제는 일반 직군의 허용 비트를 함께 판정하여 해결했다. 아이템 코드를 바꾸지 않고 18종×3직군의 일반/정예 호환성을 검사한다.

`validation/before-combat.png`는 수정 전 QA 화면이며 레벨·재화·파티 조건이 다르다. 동일 계정의 성능 비교 자료로 사용하지 않는다. 최종 경제 상태, 처치·보상 전후, UI 캡처, 비용 및 빌드 결과는 [validation/evidence-index.json](validation/evidence-index.json)에서 찾을 수 있다. 소스와 에셋 SHA-256 목록은 [change-manifest.json](change-manifest.json)에 기록했다. 비용 곡선은 저장소 루트에서 `python AI/balance/tools/analyze_beta.py`로 다시 계산할 수 있다.

카메라 경계 수정 후 패널을 3회 열고 닫는 97.78초 동안 실제 처치가 111회 증가했다. [battle-panel-progression.json](validation/battle-panel-progression.json)에 매 표본의 적·파티 위치, 스탯, 처치, 재화를 보존했다. 이 시험은 이미 성장시킨 QA 파티의 진행 안정성 확인이며 새 계정의 예상 KPM으로 사용하지 않는다.

30초 실제 전투 첫 표본은 60.10 FPS / Unity 할당 메모리 약 152MB였다. 표적 처리 수정 후 추가 표본은 **60.02 FPS, 프레임 평균 16.66ms / p95 16.70ms / 최대 33.31ms, draw call 평균 28.89 / 최대 37, Unity 할당 메모리 약 155.42MB, GC 할당 평균 3,416 B/프레임**이었다. 개발용 ARM64 IL2CPP이며 QA 부하를 포함한다. 첫 로딩은 이 표본에서 제외했고 장시간 발열·저사양 절약 효과의 검증 결과가 아니다. 새 텍스처·아틀라스를 추가하지 않았으며 UI는 기존 리소스를 사용한다.

최종 Unity 검사는 53개 계산·거래 조건과 반복 저장 40회, 직렬화 참조 11,913개, 무기 직군 호환 54쌍을 통과했다. Android에서는 실제 매니저 검사 9개를 더한 **62개 조건 + 반복 저장 40회 = 102개 통과**, 반복 파일 확정 평균 1.33ms였다. 마지막 빌드는 3분 47.49초, 오류 0 / 경고 23으로 성공했다. 경고에는 기존 비동기/미사용 코드·호환 이벤트·압축 아이콘 경고가 포함되며 경고까지 0이라고 보고하지 않는다. 마지막 실제 실행의 해당 프로세스 Unity 오류 로그는 0줄이었다.

빌드 중 바뀐 Android/URP/의존성 생성 설정은 원래 버전으로 복구했다. 기존 사용자 수정은 보존했으며 설치 APK, 기기별 캐시·계정 파일·원본 Android 로그는 커밋 대상에서 제외했다. 이 작업에서 Git 커밋이나 원격 배포는 하지 않았다.
