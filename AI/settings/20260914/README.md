# 숫자 표기와 환경설정 개편 — 2026-09-14

기본 표기는 K/M/B, 선택지는 한글 단위와 과학적 지수 표기다. 숫자가 커지는 게임에서 필요한 것은 긴 자릿수를 전부 나열하는 것보다 규모와 성장 차이를 읽는 일이다. 축약은 표시에서만 수행하며 강화 비용 비교·거래·보상·저장은 기존 정수/decimal 계산을 유지한다.

## 조사와 선택 근거

| 후보 | 예: 1,234,567,890 | 장점 | 선택 |
|---|---:|---|---|
| K/M/B 약어 | 1.23B | 짧고 초중반 K·M이 익숙하다. 1,000배 단위가 일정하다. | 기본 |
| 한글 단위 | 12.34억 | 국내 RPG 이용자가 만·억으로 읽기 쉽다. | 선택 |
| 과학적 지수 | 1.23e9 | 뒤의 지수로 규모를 직접 비교하며 매우 큰 수에도 표기 길이가 안정적이다. | 선택 |
| 알파벳 순번 | a, b, …, aa … | 단위를 계속 늘리기 쉽다. 다만 게임마다 시작 단위와 aa/ab 연결 규칙을 따로 익혀야 한다. | 이번 3종에서는 제외 |
| 쉼표로 전체 숫자 | 1,234,567,890 | 정확한 금액을 확인하기 좋지만 좁은 HUD·전투 숫자에 길다. | 재화 상세에서 유지 |
| 공학적 지수·혼합형 | 1.23e9 | 일정 지수 간격/초반 약어와 후반 지수 전환이 가능하다. | 선택지 복잡도를 늘리지 않도록 제외 |

근거 확인일: 2026-09-14. 아래 자료의 실제 사례를 바탕으로 우리 게임의 모바일 세로 화면과 현재 정수 범위를 고려해 선택했다. 장르 전체 사용률을 조사한 통계는 없으므로 K/M/B가 세계 점유율 1위라는 식으로 단정하지 않는다.

- [Kongregate — The Math of Idle Games, Part I](https://www.kongregate.com/id/pages/the-math-of-idle-games-part-i): AdVenture Capitalist 모바일 제작 참여자의 비용·생산·배수·환생 설명. 지수 비용과 성장 배수/환생이 규모를 계속 이동시킨다. 우리 게임에도 단계가 바뀌어도 일정한 단위 간격과 일관된 비용/보유량 표현이 필요하다는 설계 판단을 적용했다.
- [Idle Slayer 공식 Steam 도전과제](https://steamcommunity.com/stats/1353300/achievements/): K·M 금액과 설정 메뉴의 과학적 표기 선택이 명시되어 있다. 약어와 지수 선택지를 함께 제공하는 실제 사례다.
- [Antimatter Dimensions 공식 표기 라이브러리](https://github.com/antimatter-dimensions/notations): Standard, Scientific, Engineering, Letters, Mixed 등의 여러 방식이 있다. 다양한 표기를 조사하되 해당 코드나 종속성을 가져오지는 않았다.
- [넥슨 메이플스토리 데미지 스킨 안내](https://gi.maplestory.nexon.com/Guide/GameInformation/InfoForNewbie/DamageSkin): 억·만을 한글 단위로 표시하는 유닛 스킨을 설명한다. 국내 이용자의 읽기 경험을 고려한 한글 선택지의 참고 사례다. 메이플의 모든 표시 규칙을 복제하지는 않는다.

## 구현 계약

- 신규/기존 설치에 표기 설정이 없으면 K/M/B. 알 수 없는 설정 값은 기본으로 처리한다.
- K/M/B: 1,000배마다 K, M, B, T, Qa, Qi, Sx, Sp, Oc. 한글: 10,000배마다 만, 억, 조, 경, 해, 자, 양. 지수: 1,000부터 e 표기.
- 소수 최대 2자리, 100 이상 축약 계수는 1자리, 1,000 이상은 정수. 불필요한 0 제거. 크기가 높은 단위로 올림되지 않도록 0 방향으로 버림한다. 999,999는 999.9K이며 1M으로 보이지 않는다.
- 계정·강화 레벨, 횟수, 입장권, 시간, 확률/%는 의미에 맞는 기존 단위를 유지한다. 재화 상세의 정확한 쉼표 숫자는 축약하지 않는다.
- 재화 HUD, 비용, 보상, 공격력/체력, 장비, 스킬 피해, 전투력에 같은 표시기를 사용한다. 열려 있는 주요 화면은 표기 변경 이벤트로 갱신한다. 데미지 숫자는 48자 재사용 버퍼를 사용한다.
- 실제 계산/서버 권한은 변경하지 않는다. 표시기는 결과 문자열을 게임 계산으로 되돌리는 API를 제공하지 않는다. 로컬 환경설정은 기기 PlayerPrefs이며 서버 계정 진행 데이터와 별개다.

## 환경설정

- 세로 스크롤, 고정 제목/닫기/완료, 선택 상태와 즉시 예시, 전체 행 토글, 큰 슬라이더 터치 영역.
- 전체 음량/음소거에 배경음과 효과음 개별 음량을 추가. 전체 음소거 해제 시 이전 채널 값을 유지한다. BGM 교차 페이드 중에도 채널 음량을 곱한다. 이미 재생 중/풀에서 새로 할당하는 효과음, UI 클릭음에 같은 설정을 적용한다.
- 화면 켜짐 유지 추가: 기본은 기기 자동 꺼짐 설정을 따르고 켜면 플레이 중 절전 진입을 막는다.
- 제목 화면 우측에도 같은 환경설정을 연결했다. 제목 화면과 인게임이 동일한 설정값을 공유한다. 기존 언어 선택과 로그인도 유지한다.
- 기존 저사양과 30 FPS 절전 모드는 독립 유지. 피해 숫자 끄기는 이미 떠 있는 숫자도 회수한다. 화면 흔들림 끄기는 진행 중 카메라 변위를 즉시 복원한다.
- 사냥 장비 알림 숨기기 연결: 보상 저장 완료 후에만 알림을 보내며 숨김 상태에서도 인벤토리/보관 보상이 정상 지급된다. 반복 알림은 합치고 다른 토스트·메뉴를 가리지 않는다.
- 미지원 푸시 권한/회원 탈퇴를 실행 가능한 설정처럼 노출하지 않는다. 계정 로그인 여부가 서버 진행 저장을 뜻하는 것처럼 표시하던 문구를 현재 기기 저장 안내로 변경했다.

### 발견한 문제와 재검증

1. 슬라이더 위 세로 스와이프가 음량도 바꾸는 문제: 가로 조절과 세로 스크롤을 구분하고 탭 적용을 놓는 시점까지 미뤘다. 실제 기기에서 세로 스크롤 전후 세 음량이 유지되고 가로 드래그는 음량을 변경하는 것을 확인했다.
2. 기존 카메라 흔들림이 Cinemachine 갱신에 덮이는 문제: 설치된 Cinemachine의 실제 카메라 갱신 완료 이벤트 뒤에 변위를 적용한다. 진행 중 끄기·원위치 복원·꺼진 상태의 새 요청 차단을 최종 APK에서 통과했다. 화면 연출이 전투/드롭의 난수 스트림도 소비하지 않도록 변경했다.
3. 재화 상세의 큰 정수와 이름이 말줄임표로 잘리는 문제: 이름/아이콘과 정확한 금액을 두 줄로 나눴다. 세 표기 모두 `9,223,372,036,854,775,807` 전체 숫자와 골드·루비 이름이 잘리지 않는 것을 검사하고 실제 캡처로 확인했다.
4. 새 스크롤바 손잡이의 가로 크기가 과도한 문제: 얇은 트랙 안에 맞추고, 최종 APK의 세 비율에서 캡처로 재확인했다.

새 비트맵 자산은 추가하지 않았다. 기존 Galmuri SDF에 필요한 글리프만 보강했고 아틀라스 규격 4096×4096은 유지했다. 정적인 UI는 숫자 표기 변경 이벤트로 갱신하며, 상단 재화는 값과 표기 버전을 비교한다. 데미지 문자열 작성 10,000회는 Editor와 IL2CPP 모두 관리 힙 할당 0바이트였다. 이것은 **게임 전체 프레임의 GC가 0이라는 뜻은 아니다.**

### 재현 방법 및 한계

`AI/qa/settings/`의 `functional_suite.py`, `aspect_suite.py`, `presentation_suite.py`, `combat_suite.py`는 실제 adb 터치를 사용한다. `HUD_QA_OUTPUT`으로 출력 폴더, `HUD_QA_SERIAL`로 기기를 정한다. UI 명령 파일이 겹치지 않도록 순서대로 실행한다. Unity 종료가 adb 서버를 종료하므로 빌드와 기기 검사를 동시에 마치지 않게 한다. 최종 기능 검사는 빌드 종료 뒤 중단 없이 완주했다.

현 구현의 정수/decimal 범위까지 검증했다. 무한 정밀도 진행 재화나 미래 서버 권한 검증으로 확대 해석하지 않는다. 여러 실제 기기·iOS·장시간 배터리 소모·미지원 서버 푸시/계정 삭제는 이번 검증 범위에 포함하지 않는다. 빌드가 생성한 패키지 식별자/렌더링 사전 필터/의존성 변경과 로컬 캐시는 작업 결과에서 제외했다.
