# ComfyUI 실행 참고

행동 규칙·조달 순서·검증 기준은 [AGENTS.md](../../AGENTS.md)가 단일 출처다. 이 문서는 공정과 과거 실행에서 얻은 기술 참고만 유지한다.
모델·노드·Cloud 기능은 변경될 수 있으므로 현재 MCP 카탈로그와 입력 스키마를 다시 확인한다.

## 실행 환경

기존 공정은 `https://cloud.comfy.org`의 Comfy Cloud MCP를 사용했다. 현재 인증·연결 여부는 실행 시 확인한다.
`lobby/comfy_client.py`는 로컬에 구성된 OAuth를 이용하는 보조 클라이언트다. 인증정보는 출력·결과물에 포함하지 않는다.
과거 사용 노드: `OpenAIGPTImageNodeV2`, `GeminiNanoBanana2V2`, `LoadImage`, `SaveImage`, `Change Channel Count`, `ImageScale`, `ImageQuantize`.
이 목록은 선택 제한이나 현재 호환성 보증이 아니다. 체크포인트·LoRA·ControlNet·참조·마스킹·템플릿을 함께 탐색한다.

Cloud에서는 과거에 custom node 설치·서버 재시작·직접 파일시스템 접근이 불가능했다. `_shared` Python 도구는 로컬 독립 실행용으로도 사용할 수 있다.

## 실행·기록

1. 기존 결과와 실제 표시 크기에서 해결할 문제를 정의한다.
2. 카탈로그·노드 입력을 확인해 공정과 저비용 대안을 구성한다.
3. 버전 디렉터리에 참조·마스크·프롬프트·API JSON·UI 그래프를 보존한다. override는 실제 실행본에 병합해 별도 저장한다.
4. 저비용으로 연결·출력을 검증한 뒤 채택 공정을 발전시킨다.
5. 작업 ID·원본 출력·모델/노드 버전·실제 설정·Cloud 저장 ID/링크·비용을 manifest로 연결한다. 외부 후처리도 명령·입출력·도구 버전을 기록한다.
6. 이전 결과와 비교하고 인게임/Android 검증 후 채택한다. 지출은 사용량 조회로 보고한다.

`save_workflow(workflow_path=...)`는 과거 UI graph 포맷을 받았고 API JSON은 인라인 `workflow_json` 경로를 사용했다. `run_saved_workflow`의 override 지원과 포맷은 현재 스키마를 확인한다.
`_shared/workflow_json.py`는 API → UI 그래프 변환 도구다. 변환된 그래프와 실제 실행된 그래프를 구별한다.

## 기존 캐릭터 공정

`astra/`, `ignis/`에는 버전별 빌더·프롬프트·원본·채택본이 있다. 다른 신의 옛 설정은 신규 디자인 지시가 아니다.
기존 흐름은 마스터 1장으로 얼굴·체형·복장을 고정한 뒤 도감과 컷씬을 각각 참조 편집하는 방식이었다.
컷씬 대안 수와 seed 사용은 해당 모델의 실제 지원과 검수 문제에 따라 결정한다.

| 기존 결과 | 논리 크기 | 배율/파일 크기 | 모드 |
|---|---|---|---|
| 도감 | 256×384 | ×4 / 1024×1536 | RGB |
| 컷씬 | 288×512 | ×4 / 1152×2048 | RGBA |

부드러운 셀 셰이딩·밝은 명도·매트 피부·또렷한 선이 Astra/Ignis 파생본의 공통 화풍이다.
강한 림라이트·광택 피부·거친 텍스처를 피하고 배경은 인물보다 어둡고 단순하게 유지했다.
이는 해당 승인본의 연속성 참고이며, 신규 캐릭터의 포즈·장식·색·프레이밍을 고정하는 공통 템플릿이 아니다.

## 파일 구조

- `_shared/`: 키잉·팔레트 마감·워크플로 변환·로컬 ComfyUI 래퍼.
- `<god>/<god>_spec.py`: 캐릭터별 팔레트·프롬프트·피부/광택 대상 색.
- `<god>/build_*.py`, `finalize.py`: 공정 빌더·마감 진입점.
- `<god>/workflows/`, `output/`: 워크플로와 원본/채택본. 미채택본도 사유별 보존.
- `lobby/revision*/`: 각 버전의 실제 공정·프롬프트·검증 기록. 과거 문서의 해당 작업 한정 면제는 현재 규칙이 아니다.
- `style_spec_character.md`: 원본 에셋 측정 자료. 행동 지침으로 사용하지 않는다.

기존 이름: `<God>_00_Master`, `_01_Standing_HD/Pixel`, `_02_Cutscene_HD/Cutout/Pixel` + `.png`.
`standardize.py`는 폴더 검사 도구다. `--apply` 전에 이동 대상과 참조를 확인한다.
캐릭터끼리 마감 코드를 복사하거나 다른 신 폴더에서 import하지 않고 `_shared`를 이용한다.

## 실패 사례와 진단

| 과거 관찰 | 대응 |
|---|---|
| `ImageQuantize`가 RGBA를 거부 | 양자화 전 RGB 변환. 알파는 별도 보존·복원 |
| `background: transparent`가 카탈로그와 달리 거부됨 | 현재 검증 결과를 확인하고 충돌 없는 크로마색/마스크로 배경 제거 |
| 유료 노드 뒤에서 실패하면 앞선 출력도 회수 불가 | 저비용·최소 연결 검증. 실제 과금과 출력 회수 가능 여부 확인 |
| `Payment Required` | 추가 유료 실행을 중지하고 잔액 상태 보고. 충전은 사용자 작업 |
| 참조 파일을 `medias[].value`로 전달하면 인증 문제 | 업로드 → `LoadImage` → 생성 노드의 실제 이미지 입력 → `SaveImage` 사용 |
| GCS 서명 URL 재구성 시 403 | 반환 URL을 순서·파라미터까지 그대로 사용. 제공되면 짧은 raw 링크 사용 |
| 크로마키 뒤 닫힌 구멍/초록 테두리 잔존 | 3패스 키잉, 의상색과 분리되는 임계값 검수 |
| 전체 영역 mode 필터가 룬·윤곽 손상 | 해당 마감이 필요한 마스크/색에만 적용. 기존 도트 단순화에 사용하지 않음 |

`_shared/god_finalize.py`의 기존 처리: BOX 축소 → 팔레트 스냅 → 선택 피부/광택 정리 → 알파 이진화 → 정수배 NEAREST.
`despeckle`은 지정 밝은 색의 고립 픽셀만, `unify`는 지정 피부색만 처리하며 마스크 밖 색을 투표에 넣지 않는다.
신규 작업의 품질 문제에 맞지 않으면 이 과거 체인을 강제하지 않는다.

## 출력 검사

기존 `finalize.py`는 크기·팔레트 외 색·알파 이진·정수배 블록을 검사한다.
추가로 실제 표시 크기/확대에서 손·얼굴·직선 무기 구조·캐릭터 동일성·프레임 잘림·배경 잔여물을 확인한다.
가장자리 접촉 픽셀 수는 잘림 진단의 보조 지표다. 자동 수치와 인게임 육안 검수를 함께 사용한다.
