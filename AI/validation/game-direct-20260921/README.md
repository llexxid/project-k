# 기능 안내 0.15.0 검증 기록

## 구현 범위

자동 발생 조건을 제외한 1~3단계다. `GameDirectManager`는 bootstrap의 영속 GameManager에 붙어 FIFO·ID 중복 방지·계정 세대·진행 저장을 관리한다. 일반 C# `FeatureGuidePlayer`는 한 단계의 표시와 응답을 맡고 `UguiFeatureGuideSurface`를 통해 실제 `FeatureGuideView` 프리팹을 사용한다. 기존 TutorialManager·QuestManager 진행은 연결하지 않았다.

`first_start_menus`는 육성 → 왕국군 → 던전 → 뽑기, `first_reincarnation_guide`는 환생 소개다. 환생 정책을 추가하거나 실행하지 않는다. 새 데이터와 재생 방법은 [UGUI 안내](../../../Assets/UGUI/README.md#공통-연출과-기능-안내)에 있다.

## Unity 검증

- Unity **6000.3.21f1**에서 import·컴파일 성공. 실제 프리팹 생성, 카탈로그 참조, bootstrap 관리자와 두 SO 연결을 Editor API로 저장했다.
- 최종 `acceptance.json`: **181개 검사 항목 통과**. 동작 검사와 컴포넌트별 직렬화 참조 검사를 합산한 수다. 운영 계정을 사용하지 않는 빈 PlayMode 씬과 별도 테스트 계정으로 실행한다.
- 네 단계/최종 확인, 환생 대상, 투명 강조 구멍을 통한 메뉴 터치 차단, 연타, FIFO/중복 ID, 완료·건너뛰기 억제, 미리보기 저장 무변경, 단계 저장 후 계정 재로드/재개를 확인했다.
- 시스템 취소와 사용자 건너뛰기 구분, `RequestBack()`의 skip 경로, 팝업·로딩·화면 교체·숨김/파괴된 대상, 관리자 비활성화, 계정 변경 시 큐 폐기, 이전 계정 세대의 저장 거절을 확인했다.
- 격리 저장 경로에 의도적으로 쓰기 실패를 발생시켜 입력 차단 해제·미확인 단계 유지·다음 요청 재시작을 확인했다. 저사양 모드에서 강조 호흡만 멈추고 버튼·설명이 유지됨을 확인하고 설정을 복원했다.
- 스테이지 전환의 기존 환생 처리 `ReincarnationService.CommitAtBoundary`는 `Modules`를 제거하지 않는다. 안내 저장도 기존 계정 저장의 별도 모듈 키만 사용한다.

## 발견 문제와 수정

1. 최초 검사에서는 팝업 레이어에 상시 존재하는 `Hud_Party`를 모달로 판단하여 안내가 대기했다. `PartyHudView`를 제외하고 실제 활성 팝업은 계속 차단하도록 수정했다. 실패 결과 `acceptance-r1-failure.json`, `acceptance-r2-failure.json`을 보존했다.
2. 환생 본문이 360×800에서 할당 높이를 넘었다. 본문 선호 높이에 제목·버튼 영역을 더해 카드 높이를 결정하고 버튼 높이를 86→132, 본문 크기를 30→36으로 조정했다. 실패 결과 `acceptance-r3-failure.json`을 보존했다.
3. 수정 후 176개 검사 통과, 대상 파괴·저사양·관리자 비활성화 검사를 보강한 뒤 최종 181개 검사 통과. 실행 도구의 5초 응답 제한에 걸린 호출도 실제 실행 결과 파일로 완료 여부를 확인했다.

## 화면·비용

`before-*`, `menu-1-*`~`menu-4-*`, `reincarnation-*` 18장은 **실제 UI 프리팹을 격리 씬에서 RenderTexture로 렌더한 비율 시뮬레이션**이다. 360×800(긴 폰), 540×960(16:9 폰), 900×1200(태블릿)을 검사했다. 각 안내의 카드가 Safe Area 루트 안에 있고 본문 overflow가 없는지 검사했다. 실제 노치·OS 인셋·터치 밀도 검증은 아니다.

| 비율 | 안내 전 batches | 안내 중 batches | 총 할당 메모리 전/첫 안내 |
|---|---:|---:|---:|
| 360×800 | 18 | 23~24 | 438,955,562 / 439,037,738 bytes |
| 540×960 | 18 | 23~24 | 440,907,723 / 440,985,331 bytes |
| 900×1200 | 18 | 23~24 | 444,748,152 / 444,812,520 bytes |

이 측정에서 draw calls는 batches와 동일했다. 대략 **5~6 batches 추가**다. 메모리는 캡처 텍스처·Editor·기존 UI·측정 코드가 포함된 전체 할당 값이므로 차이를 안내 전용 메모리나 실기기 사용량으로 해석하지 않는다. 새 텍스처·폰트·개별 TMP 머티리얼을 만들지 않고 공용 리소스를 참조했다. 기존 Galmuri11 SDF 아틀라스에 빠져 있던 `뛰` 글리프 하나를 추가한 결과는 보존했다. 좌표 변경이 없을 때 텍스트·RectTransform을 다시 쓰지 않는다.

`live-menu.png`, `live-reincarnation.png`는 bootstrap에서 기존 일반 게스트 로그인 버튼을 통해 진입한 **Editor 실제 전투 화면**이다. 게임 계정에 안내 완료를 남기지 않는 preview만 사용했다. `live-samples.jsonl`에서 약 20.8초 동안 처치 수 28,927→28,943, timeScale=1, 안내 표시 유지가 확인된다. 환생 미리보기 확인 후 육성 메뉴가 열리는 것도 확인했다. 소스 화면을 540×960으로 캡처한 결과이며 물리 기기 사진이나 별도 해상도 실기기 테스트가 아니다.

## Android 상태

사용자의 최종 지시에 따라 **코드 추가와 Unity PlayMode 테스트까지만 진행**했다. 시작되어 있던 Android 빌드는 네이티브 컴파일 중 중단했으며 빌드 성공이나 APK 검증으로 기록하지 않는다. APK 생성·실기기 설치·뒤로가기 하드웨어 입력·앱 백그라운드 복귀·실기기 로그인·전투·메뉴 검증은 이번 범위에서 제외했다. 위 뒤로가기 검사는 동일한 `UIManager.RequestBack()` 경로를 호출한 Editor 검사다. 기기 파일/다른 앱/기존 설치본은 건드리지 않았다.

중단 시 먼저 예약했던 지연 호출도 뒤늦게 실행되어 해당 빌드 프로세스까지 종료했다. 빌드 도우미가 예약한 versionCode 59·60은 재사용하지 않도록 최종 코드를 60으로 유지한다. 앱 이름·패키지·서명·ABI 등 임시 설정은 복원했고 최종 게임 버전은 0.15.0이다. Android QA 명령 진입점은 코드만 추가했으며 이번에는 기기에서 실행하지 않았다. 두 시도 모두 사용자 지시로 중단했으므로 빌드 검증 성공을 의미하지 않는다.

## 다음 연결

4단계: 계정 생성 결과의 신규 여부를 명확히 구분하고 메인 준비 시 `RequestPlay("first_start_menus")`를 요청한다. 오래된 계정에 안내 키가 없다는 사실만으로 신규 계정이라고 판단하지 않는다.

5단계: 안내를 소개할 환생 스테이지 기준을 확정한 뒤 스테이지 진입·로그인 복구 시 `RequestPlay("first_reincarnation_guide")`를 요청한다. 실제 환생 실행 가능 조건은 기존 서비스가 소유한다. 중복 이벤트와 완료 억제는 공통 Manager가 처리한다.
