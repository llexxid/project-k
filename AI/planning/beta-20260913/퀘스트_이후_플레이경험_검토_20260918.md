# 퀘스트 이후 플레이 경험 검토

검토일: 2026-09-18. 기획 폴더의 DOCX 3개, XLSX 2개(전체 시트), 기획데이터 TXT, 개정 검증 기록과 현재 코드·직렬화 데이터·구현 기록을 대조했다. 기존 미커밋 변경을 포함한 상태를 읽었으며 게임 코드는 수정하지 않았다.

이번 결과는 문서와 구현으로 플레이 흐름을 추적한 기획 추천이다. 최신 빌드에서 직접 플레이하거나 완료 시간을 새로 측정한 결과는 아니다. 아래 우선순위와 규모는 제안이며 확정 일정이 아니다.

## 판단

다음 개발의 중심은 **첫 목표를 실행할 수 있는 안내, 실패에서 배우는 재도전, 복귀 시 성장 체감, 편성에 따라 달라지는 전투, 베타 완주 후 다음 목표**다. 퀘스트는 행동의 목적을 제공하지만 이 연결을 자동으로 완성하지는 않는다.

베타 개정서 12장의 미구현 목록은 9월 13일 당시의 상태다. 현재는 성장 경제, 던전 규칙, 오프라인 정산, 환생, 퀘스트 집계·수령의 상당 부분이 구현되어 있으므로 같은 항목을 신규 개발로 다시 잡지 않는다.

## 추천 순서

규모의 소/중/대는 기존 화면 연결 / 표시·상태 확장 / 아트·전투 콘텐츠 제작을 대략 구분한 상대 평가다. 세부 설계와 기기 검증 전에 작업 일수를 확정하지 않는다.

P0는 이번 검토에서 체감 개선을 먼저 할 항목이라는 뜻이다. 원 기획서의 데이터 손실 방지용 P0와 동일한 분류표가 아니다. 신규 유저가 이미 3스테이지를 빠르게 소진한다는 실측이 나오면 후속 콘텐츠 제작 순위를 올린다.

## 구체적으로 확인한 근거

### 1. 목표와 실행 경로

- `GuideGoalView.cs:143`의 목적지 매핑은 `SkillEquip`를 왕국군 화면으로 보내며 `SkillEnhance`, `SkillAwaken`, `Reincarnate`의 목적지가 없다. 장비·전직도 대상 병사와 세부 탭까지 지정하지 않는다.
- 카탈로그 `02_가이드`는 G10 첫 보스, G14 첫 전직, G16~G18 마탑 뽑기·장착·강화를 요구한다. 첫 마법은 그보다 앞선 1-5에서 지급된다. 기능이 열리는 순간의 짧은 안내를 가이드 진행과 별도로 설계할 가치가 있다.
- 최초 스킬은 빈 슬롯에 자동 장착된다(`BattleEconomy.cs:362`). 따라서 초반에 마법을 장착하지 못해 반드시 막힌다고 해석하지 않는다.
- 기획서 §13.2는 스테이지 도달 시점이 아직 확정되지 않았다고 명시한다. 첫 강화·첫 마법·첫 전직·첫 보스에 도달하는 예상 시각과 이탈 시 대응을 기획표에 추가하고 실측으로 조정한다.

### 2. 실패를 다음 행동으로 연결

- 보스 실패 후 이전 일반 웨이브 반복과 보스 자동 도전 해제는 이미 구현되어 있다(`StageManager.cs:553`).
- 타임아웃은 일반 전멸 처리와 같은 경로로 전달된다(`StageSession.cs:188`). 현재 안내는 성장 후 재도전을 권하는 문장 수준이다(`WaveUIController.cs:154`).
- 추천은 실제 기록에 기반한다. 예를 들어 시간 초과 시 남은 HP를 보여주고 공격 수단을 살펴보게 한다. 전투력만으로 승리를 보장하거나 원인과 무관한 구매를 권하지 않는다.
- 던전은 각 2장의 무료 입장권과 실패 소모가 있으므로, 상위 단계 진입 전 지난 기록·보상·실패 조건을 이해할 수 있어야 한다. G23/G24의 던전 클리어에서 입장권 소진으로 가이드가 다음 날까지 멈추는지 관찰한다. 입장권 정책 변경은 관찰 후 별도 설계한다.

### 3. 일일과 복귀의 마무리

- `BalanceQuestPanel.cs:50`은 가이드·일일·주간·업적을 하나의 목록에 이어 붙이고 수령 완료 행을 숨긴다. `:71`의 헤더는 범주 문자열이며 일일 5/7 요약은 없다.
- 개별 수령과 이전 기간 보관 표시는 있으나 일괄 수령, 초기화/만료 시각, 수령 결과 합계 표시는 없다. `QuestContracts`에 기간·만료 데이터가 있어 표시 확장의 기반은 있다.
- `UIManager.cs:707`의 가이드 배지 갱신은 현재 아무 작업도 하지 않는다. 새 알림을 넣을 경우 실제 수령 가능 상태에만 반응하게 한다.
- 오프라인 팝업에는 획득량·레벨이 나오지만 확인 버튼은 닫기만 한다(`OfflineRewardPopupController.cs:81`). 기존 강화의 1/10/MAX 기능을 활용해 성장과 재도전으로 연결한다.
- 일일 420초는 실제 전투 시간이다. 메뉴를 찾고 보상을 받는 시간이 길어지면 총 10분 목표를 초과한다. 일일을 끝낸 상태와 추가 주간 플레이를 분명하게 구분한다.

### 4. 선택의 재미가 생기는 위치

- 마탑은 슬롯 5개, 베타 스킬 3종, 같은 스킬 중복 장착 금지다(`MageTowerManager.cs:22`, `:181`; 기획데이터의 마탑 장착 규칙). 현재는 보유한 세 스킬을 모두 장착할 수 있어 장착 슬롯 경쟁이 주된 전략이 되기 어렵다.
- 의미 있는 선택은 3인의 직업·무기와 마탑 강화 투자 배분에 있다. 이 선택이 실제 생존 시간·보스 화력·다수 적 처리 속도에 드러나는지를 먼저 확인한다.
- 다른 직업의 최초 해금은 캐릭터별 40파편을 사용한다. 이미 해금한 직업만 무료 재전직이다. 반복 고정 파편 수입 36개/주라는 설계에서는 직업 실험과 첫 2차 전직 저축이 경쟁한다. 프리셋만으로 이 문제를 해결할 수는 없다.
- 최소 개선은 전직 전 역할·예상 변화·비용 설명이다. 유저가 선택을 꺼리는 현상이 확인되면 보상 없는 체험 등을 검토하며, 이번 추천만으로 무료 해금 정책을 바꾸지 않는다.
- 새 적의 차이는 자동 전투의 생존·단일 화력·광역 투자에 의미를 주는 정도부터 시작한다. 복잡한 수동 회피나 다수 신규 성장 축을 전제로 하지 않는다.

### 5. 예정된 콘텐츠의 실물 완성

- 수치 구현 기록은 2스테이지에 BanditShield/Archer, 골드 던전에 ORC 외형을 임시 사용한다고 명시한다(`AI/balance/20260913/README.md:66`). 현재 StageDatabaseSO에서도 해당 적 참조를 확인했다.
- 기획의 고블린·신규 오크·미믹 제작 완료와 수치상 33웨이브/던전 10단계 구현 완료는 구분해야 한다.
- 아트 교체는 모바일 실제 크기의 적 식별, 동시 6체 전투 가독성, 메모리·드로콜 비용을 포함해 검증한다. 이번 검토에서는 아트를 새로 제작하지 않았다.

### 6. 완주 이후에도 남는 목표

- 3-11 이후 3-10 반복 사냥은 구현되어 있다(`IStageRule.cs:89`). 최초 클리어 보상도 지급된다(`BattleEconomy.cs:351`).
- 확인한 메인 클리어 경로에는 베타 완주와 다음 성장 목표를 안내하는 전용 화면이 없다. `UIManager.cs:207`의 클리어 팝업 처리는 던전 대상이다.
- 첫 7일에 무엇이 새로 열리는지 기획표가 필요하다. 첫 전직·각성·1/2/3스테이지·첫 2차 전직·던전 상위 단계의 실제 도달 시각을 바탕으로 일정을 만든다.
- 첫 2차까지 약 8일이라는 문서 계산은 모든 일회성 파편을 얻고 3인 1차 외에는 쓰지 않았다는 가정의 추가 수급 기간이다. 신규 계정의 도달일 보장이 아니다.
- 4스테이지 이후는 새 적·배경·보상과 전투 역할이 있는 콘텐츠로 확장한다. 3스테이지가 너무 빨리 끝나는 문제를 임의의 HP 벽이나 강화 상한 채우기로 대체하지 않는다.

### 7. 장비 편의의 현재 범위

- 단건 분해·잠금·보관함 수령은 이미 존재하며 왕국군 장비 화면에서 호출한다(`EquipmentManager.cs:105`, `:110`, `:122`; `KingdomArmyPanelController.cs:494`, `:634`). 새 기능으로 다시 구현할 항목이 아니다.
- 독립 인벤토리 화면은 강화 중심이고 재료/기타 탭은 빈 안내를 표시한다. 관리 기능을 찾는 경로와 일괄 작업을 정리할 여지가 있다.
- 가방 300/보관함 100, 보관함 안전 여유 부족 시 전투 보류가 있으므로 실제 며칠 차에 정리가 부담되는지 측정해 우선순위를 조정한다.

## 먼저 실행할 작은 작업 묶음

1. **신규 플레이 연결**: 가이드 목적지와 대상 탭을 완성하고, 1-5 마법·1-11 보스/일일/던전·첫 전직의 해금 안내를 정리한다.
2. **한 세션 완성**: 일일 5/7 요약·수령·종료 상태, 실패 결과와 성장 이동, 오프라인 결과와 성장 이동을 연결한다.
3. **기존 콘텐츠의 차별성**: 3인 직업과 마탑 투자 전후를 비교하고, 임시 적 외형과 지역·던전의 식별을 완성한다.
4. **7일 관찰과 확장 결정**: 베타 완주 후 목표를 제공하면서 실제 소진 속도에 따라 후속 스테이지 제작 범위를 정한다.

## 완료 판정과 검증 범위

기획 문서의 기존 목표를 사용한다. 새로 측정한 수치가 아니다.

- 일일 5개 완료 보상까지의 실제 소요시간: 중앙값 8~12분, P90 15분 이하. 메뉴·로딩·수령을 포함한다.
- 복귀: 오프라인 결과 확인 후 1분 안에 성장과 사냥 재개.
- 무료 경로: 구매·광고·유료 뽑기를 강제하지 않고 일일 완료. 주간 210분과 추가 20~30분 플레이는 선택 목표로 구분.
- 최소 7일: 신규/이관 계정, 일일 10분/30~40분 이용을 구분. 첫 전직·각성·스테이지 도달 시각, 실패 원인, 던전 승률, 성장 전후 기록, 재화 유입·소모·잔액을 관찰.
- 첫 세션 행동별 체류·이탈과 3-11 이후 선택 목표를 기록해 순위를 조정한다. 현재 자체 런타임 코드 조사에서는 이를 수집하는 전용 분석 이벤트를 확인하지 못했다. 측정 설계도 작업 범위에 넣는다.

9월 14일 경제 개편에는 Android 한 대의 실기기 검증 기록이 있다. 반면 9월 17일 퀘스트의 221개 검사는 격리 Unity 하네스 결과이며, 그 기록에는 원본 최종 import/참조 검사와 Android 터치·복귀·실제 전투 검증이 남아 있다. 과거 경제 검증을 최신 퀘스트 기기 검증으로 대신하지 않는다.

추가 일일 숙제, 새 재화·장비 슬롯, 유물·마석, 명명 파티 보너스, 랭킹 중심 경쟁, 대규모 신규 마탑은 현재 루프의 선택감과 콘텐츠 소진 속도를 확인한 뒤 검토한다. 신 스킬은 보류가 아니라 현 기획에서 폐기 확정된 항목이다.

사업소개서와 정리본의 시즌 패스·성장 펀드는 판매 검증 후보로 해석한다. 베타 개정서의 BM 보류와 혼합해 지금 필수 게임플레이 기능으로 올리지 않는다. 무료 진행 검증 후 보상 수량과 조건을 확정한다.

현재 경제 권한은 `local-client`이며 서버 시간 검증·다중 기기 동시 승인 범위는 남아 있다. 저장 보존·복구, 보상 서버 권한과 기간 검증은 외부 서비스/판매 전 별도 선행 과제다. 이는 새 콘텐츠의 재미 순위와 별도로 관리한다.
