# 2026-10-01 배경 두 번째 개정

## 적용 내용

- 기존 90개 프리팹과 미리보기 번호를 유지한다. 물 타일과 연못 생성 경로를 제거했다.
- 흙길 일부와 풀길 전체에 연결된 공터를 만든다. 진입로는 4~5타일, 중앙 공터는 7~8타일로 넓혀 직선 도로와 구별한다. 구매 원본의 연두색 풀길 및 볼록·오목 전이 타일을 사용한다.
- 공터 외곽에 소나무·자작나무·둥근나무·버드나무를 혼합했다. 중앙 장식 대신 상하 모서리에 나무를 보강한다.
- 던전 `Crates`가 실제 양문형 나무문, `Vines`가 매다는 천, `StoneRubble`이 금속 고리로 보이는 원본임을 확인했다. 독립 배치를 제거하고 생성·검증 단계에서 재사용을 막았다. 낮은 가로 격자 소품은 가구로 단정하지 않고 `StoneGrate` 테마로 기록한다.
- 기둥은 프리셋 전체에 0~2개다. 2개는 같은 높이의 양쪽 짝으로 배치하며, 긴 폰에서도 보이도록 전투 영역 위·아래에 놓는다. 추가 무작위 기둥은 없다.

## 전투 시야와 표시 순서

이전 중앙 여백 x±2.1875는 실제 전투원 이동 ±2.48 및 생성 ±2.5보다 좁았다. 활성 몬스터 15종의 원본 idle 몸체 측정 자료를 기준으로 일반·특수 x±3.1875, 보스 x±3.25로 넓혔다. 이는 무기·모든 공격 자세의 최대 실루엣 측정과는 다르다. y -3.125~4.5의 보호 사각형은 소품의 전체 bounds와 겹칠 수 없다. 위·아래 모서리에는 전체 스프라이트가 보호 사각형 밖일 때만 안쪽 배치를 허용한다. 모든 일반 소품에 네이티브 4픽셀 간격 예약을 적용한다.

실제 배경은 Default 레이어의 -300/-290/-280 순서다. 전투원·장판·단발 효과와의 관계는 정적 설정, 실제 플레이 렌더러, 고정된 한 프레임의 배경 유무 픽셀 비교로 각각 확인한다. 새 `StageEnvironmentDiagnostics`는 Editor 및 명시적 진단 빌드에만 포함되며 상태를 바꾸지 않는 읽기 진단이다. 상용 전투 로직·배경 선택 로직은 변경하지 않았다.

몸체 측정과 한계는 [공간 감사](runtime-spatial-audit.json), Android 범위는 [기기 기록](device-summary.json)에 있다.

## 검증과 재현

- `EnvironmentPolishValidation.PrepareAndCaptureAfter`: 90개 저장 프리팹, 기준 화면90장 및 다른 비율45장. 물·금지 소품·기둥 수/짝·보호 사각형 침범·소품 중첩·누락 참조·충돌체·지면 공백을 검사한다.
- `EnvironmentGameplayValidation.PrepareAndRun`: 위 생성/렌더에 이어 실제 bootstrap/main/던전 Play Mode를 실행한다. `Run`은 생성/정적 렌더를 반복하지 않고 Play Mode만 실행한다. 기존 계정과 구분되는 로컬 전용 테스트 계정을 사용하며 클라우드 로그인 공급자를 호출하지 않는다. 실행 전 기존 저장 파일과 `.bak`을 별도 비공개 경로에 바이트 그대로 보관하고, 모든 종료 콜백이 끝난 뒤 계정 복원과 원본 바이트 일치를 검사한다. 보고서를 통과시키기 위한 파일 덮어쓰기나 자동 복구는 하지 않는다.
- 게임 플레이 검사는 실제 전투원과 프리팹90종의 렌더 순서, 검정·흰색 배경으로 분리한 불투명 픽셀의 가림, 3개 화면 비율의 월드 캡처, 일반 라이트닝과 공허 균열의 실제 시전을 대상으로 한다. 캡처에서 모든 Canvas를 잠시 숨기며 HUD·체력바 위치·안전 영역 검증을 주장하지 않는다. 최종 실행 결과는 [final/gameplay/report.json](final/gameplay/report.json)에 기록했다.
- 배경 비교는 실제 진행 중인 전투에 저장된 배경 프리팹을 잠시 대입한다. 해당 배경의 모든 웨이브를 자연 진행했다는 의미가 아니다. 화면 비율은 Editor 렌더이며 여러 물리 기기를 뜻하지 않는다.
- 컴파일·자동 검사 이후 90장 연락판 및 지적된 28·57·62와 긴 화면 대표를 사람이 볼 수 있는 크기로 다시 확인한다.

현재 번호별 렌더는 [after/index.html](after/index.html), 이번 수정 전 렌더는 [이전 after](../after/index.html)에 있다. 라이트닝91번은 이전 개정 결과를 그대로 유지했다. 외부 이미지 생성은 호출하지 않았다.

최종 Unity Play Mode 실행은 통과했다. 90개 프리팹 모두 렌더 순서 및 540×960 픽셀 가림 검사를 통과했고, 대표 15개 프리팹은 432×1008·720×960의 추가 30회 검사도 통과했다. 실제 비개화 라이트닝의 번개 이벤트는 3회였으며 공허 균열과 함께 시전 중 렌더 순서·픽셀 가림 검사를 통과했다. 종료 후 기존 파일 164개가 전부 바이트 단위로 동일했고, 기존 계정 컨텍스트 복원도 확인했다.

피격 효과는 우연히 잡힌 전투 프레임에 의존하지 않도록 별도 검사를 추가했다. 실제 생성된 적에게 실제 플레이어를 소유자로 하는 `Monster.TakeDamage` 경로로 1 HP의 제어된 피해를 적용했다. 같은 적의 HP 189→188, 렌더러 속성 `_FlashAmount` 0→0.45→0을 기록했으며 마지막 복원은 실제 코루틴 실행 0.100000143초 후 확인했다. 기본 상태·피격 중·복원 후 세 단계 모두 전체 전투원과 해당 적만의 불투명 픽셀 가림 및 렌더 순서를 통과했다. 재질 교체 없이 동작했다. ## 첫 실제 실행에서 발견한 검수 코드 문제

첫 Play Mode 실행에서 배경90종의 렌더 순서·픽셀 가림 검사와 두 스킬 검사는 통과했다. 하지만 테스트 종료 전 기존 계정을 복원하자 아직 살아 있던 게임 리스너 및 종료 콜백이 에디터 `local-guest`의 일일/주간 관찰 시각·활동 시각·리비전 메타데이터를 갱신했다. 기존 파일1개의 해시가 달라져 전체 결과는 실패로 남겼다. 휴대폰 저장과 클라우드 계정은 이 실행에서 접근하지 않았다. 첫 실행의 `.bak`도 종료 중 만들어졌으므로 원본이라고 가정해 복구하지 않았다.

또한 캡처에서 체력바가 분리돼 보였다. Overlay HUD를 다른 비율의 카메라 렌더 텍스처로 옮기는 동안 체력바의 화면 좌표를 다시 계산하지 않은 캡처 경로를 확인했다. 이 캡처는 실기기에서 체력바가 잘못됐다는 근거로 사용하지 않는다. 후속 검사는 Canvas 설정을 바꾸지 않는 월드 전용 캡처로 범위를 명시했다. [첫 실패 보고서](gameplay/report.json)와 첫 캡처는 그대로 보존한다.

## 재실행에서 발견한 실제 셰이더 설정 문제

[두 번째 실행](verified/gameplay/report.json)은 기존 파일 162개를 모두 보존했지만 첫 배경의 렌더 순서 검사에서 실패했다. 실제 적의 `MonsterHitFlash` 재질 렌더 큐가 2000이고 배경은 3000인 점을 포착했다. 해당 실행의 픽셀 비교에서는 실제 불투명 몸체 가림이 관찰되지 않았으므로 이미 발생한 가림 현상으로 단정하지 않는다. 셰이더 그래프의 3D 정렬 호환 경로가 불투명 Mesh 패스와 깊이 쓰기를 사용하던 설정을 확인했다.

그래프를 Transparent, ZWrite ForceDisabled, SpriteUnlit의 2D 정렬 경로로 수정하고 관련 재질의 큐를 3000으로 고정했다. 그래프의 색·알파·점멸 계산 노드는 유지했다. 노출되지 않은 `_ZWrite` 속성은 보고서에 `null`과 `hasDepthWriteProperty=false`로 기록한다. 속성 부재를 깊이 쓰기 비활성의 증거로 해석하지 않으며, 그래프 소스 설정 검증과 실제 렌더 큐·GPU 픽셀 검사를 별도 증거로 남긴다. 두 번째 실패 보고서를 보존하고 위 최종 실행에서 수정 및 점멸 전후 검사를 통과했다.

## 비용과 미검증 범위

추가 배경 텍스처·런타임 장식 오브젝트·충돌체 없이 기존 3개 TilemapRenderer를 유지한다. [개정 전후 셀 수](tile-cost-comparison.json)에서 숲 54종의 소품 셀은 843→945개, 던전 18종은 234→136개다. 전체 지면 셀 수는 같고 바닥 디테일 셀은 1,636→1,482개다. 이는 셀 수 비교이며 GPU 비용 감소를 직접 증명하는 지표는 아니다. Editor의 제어된 시뮬레이션 시간을 실제 기기 FPS로 해석하지 않는다. 계정 선택이 필요한 실기기 로그인·전투는 완료된 검사와 별도로 기기 기록에 명시한다.

## 연결된 Android 최종 결과

[실기기 요약](device-summary.json)과 [빌드 기록](android-builds.json)을 확정했다. Samsung SM-N986N 한 대의 실제 1080×2316 화면에서 검수했다. b67은 별도 Android 패키지·UID와 실행마다 고유한 로컬 검수 계정을 사용하는 앱이다. 기존 앱에 테스트 진행도나 재화·스킬을 주입하지 않았다. 실제 지역·던전 전투에 배경을 대입해 90종을 비교했으며 모든 웨이브를 자연 진행한 기록은 아니다.

- [배경 90종](device/backgrounds.json): 전투 진행, 실제 표시 순서, 같은 프레임 GPU 픽셀 검사를 통과했다. 배경에 의해 바뀐 불투명 전투 픽셀은 0개이며 배경 충돌체도 0개다. 01–90 원본 캡처와 [무결성 목록](device/capture-integrity.json)을 보존했다.
- [실제 시전](device/skills.json): 비개화 라이트닝의 실제 원본 스프라이트·3회 낙뢰·피해 이벤트와 공허 균열, 일반 아이콘 표시를 확인했다. [실제 피격](device/hit-flash.json)은 1 HP 피해 전·점멸 중·실제 코루틴 복원 후 세 단계와 대상 적만의 픽셀 검사도 통과했다.
- [실제 터치/뒤로가기](device/touches.json): 육성·왕국군·던전·뽑기·설정의 다섯 경로를 Android 터치와 하드웨어 Back으로 확인했다. 네이티브 화면에서 체력바 분리 현상은 보이지 않았다. 기둥 상단 일부는 의도적으로 HUD 뒤에 있고, 전투 공간에는 들어오지 않는다.
- [연속 전투 측정](device/performance.json): 추가 픽셀 읽기나 명령 없이 약 20초 동안 1,226프레임을 관측했다. 평균 프레임 시간은 16.78ms, 환산 59.61fps였다. b67 한 기기의 짧은 관측이며 b66 대비 성능 향상이나 장시간 안정성을 주장하지 않는다.

새 검수 계정의 던전 해금 이력을 준비하지 않아 첫 던전 입장이 거부된 경우와 검수 도구의 삼성 창 상태·설정 패널 판정 문제를 기록하고 수정했다. 85번은 정상 던전 종료 팝업이 겹쳐 해당 장면만 재입장·재검사·재촬영했다. 이전 캡처는 비공개 작업 기록에 보존했고, 이후 드라이버는 전투 Running 상태와 팝업 부재를 함께 검사한다. 나머지 89번의 원래 촬영 후 상태도 Running이었다.

검수 전후 기존 앱 저장·설정 59개가 동일했다. 최신 데이터를 다시 백업한 뒤 일반 로그인용 **0.15.2(b68)**를 업데이트로 설치했고, 설치 직후에도 59개 파일이 동일했다. [설치 결과](device/installed.json), [정리 결과](device/cleanup.json)에 기록했으며 테스트 앱은 백업 후 제거했다. 휴대폰에는 최신 일반 앱 한 개가 남아 있다. 타이틀의 `v0.15.2`와 Google 계정 선택 화면 진입까지 확인했다. [본인 계정 선택](device/natural-login-status.json)은 사용자가 해야 하므로 해당 계정의 인증 후 전투는 미검증 상태로 명시한다. 계정 선택 화면·개인 계정 식별자·저장 내용과 백업 원문은 공개 미리보기 및 Git 기록에서 제외했다.
