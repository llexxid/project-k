# 전투·마탑 개정 검증 — 2026-09-16

## 적용 범위

Unity **6000.3.21f1**을 유지하고 게임 버전은 **0.10.0**으로 올렸다. 외부 원본은 수정하지 않았으며, 캐릭터·스킬 ID와 에셋 GUID를 보존했다. Stage_Catalog → StageDataGenerator → StageDatabaseSO 경로를 유지한다.

최종 Android IL2CPP 빌드(`Iteration7c`, versionCode **9**)는 오류 0개·경고 22개로 성공했다. APK는 81,217,636바이트다. 상세 성능 표본은 같은 전투 로직의 직전 code 7 빌드에서 측정했고, 최종 빌드는 폭탄의 아틀라스 포함 및 명시적 참조 비교를 추가했다. 기존 미사용 이벤트·obsolete API 등 컴파일 경고를 모두 제거한 빌드는 아니다.

- 근접 병사와 몬스터는 발 위치를 기준으로 대상 옆에 접근한다. 최소 전방 간격과 상하 허용 범위를 타격 시점에도 재검사한다. 공격 중 대상이 사망·부활·풀 재사용되면 이전 판정을 취소한다.
- 병사 공격 간격은 창병 1.2초, 기사 1.65초, 정예 기사 1.75초, 마법사 1.6초, 정예 마법사 1.65초다. 강한 한 방의 피해 배율과 전투력 계산도 함께 조정했다. 몬스터 41개 카탈로그 행에 콘셉트별 이동·공격 간격·공격 배율을 반영했다.
- 원거리 병사는 공격 뒤 가까운 적을 피해 최대 0.7초 이동한다. 강철 의지는 최대 HP 20% 보호막을 5초 유지하고 주변 첫 도발 소유권을 기사 생존 중 유지한다. 에너지 파동은 일반 적을 밀치고 1.25초 기절시키며 보스에는 피해만 준다.
- 투척 몬스터는 공격 클립의 발사 시점에 투사체를 내보내고 도착 때 피해를 준다. 이동으로 회피할 수 있다. 오크 투창은 이미 기울기가 들어 있는 원본 애니메이션을 다시 회전시키던 문제를 수평 프레임과 실제 비행 방향 회전으로 해결했다.
- 궁수 두 전직의 사용·선택·전투 노출을 막았다. 기존 편성은 창병으로 이전하고 소유 장비·해금·강화 투자는 보존한다. 전직 트리는 창병 실루엣과 `곧 추가 예정`인 비활성 노드 두 개를 표시한다.

## 마탑·UI·사운드

시전 카운터 저장에서 매번 JSON 복사·동기 저장하던 경로를 명시적 깊은 복사와 짧게 묶은 비동기 저장으로 바꿨다. 재화 거래는 선행 저장과 순서를 맞추고 앱 일시정지·계정 전환에서 남은 카운터를 저장한다. 슬롯과 스킬의 쿨타임을 각각 유지해 교체로 재사용 시간을 우회하지 못하게 했다. 장착 UI는 슬롯 선택 → 스킬 선택 → 장착/교체이며 이미 다른 슬롯에 있는 스킬은 원자적으로 맞바꾼다.

유성우(ID 3)는 전장 곳곳의 적을 향해 하늘에서 별빛을 떨어뜨린다. 공허 균열은 허공의 큰 원 안에 몸체 중심이 있는 적만 흡인하고 보스에는 흡인이 적용되지 않는다. 운석은 불투명한 회전 몸체와 움직이는 불꽃을 사용한다. 천벌은 회색 먹구름과 내부 보라색 뇌전, 확대한 기존 Lightning 1 낙뢰를 사용한다. 즉발 타격은 몬스터 앞, 지속 장판은 뒤에 표시한다. 독 장판은 풀과 구별되도록 작업본의 팔레트·불투명도를 다시 조정했다.

설정은 화면·소리·기기 탭으로 나눴다. 전체/음악/효과음에 더해 왕국군·몬스터·마탑·인터페이스 효과음을 따로 조절한다. 전투 효과음은 6개 풀, 왕국군 최대 2개·몬스터 최대 3개 동시 음원, 전역·동일 효과 재생 간격 제한을 사용한다. 최종 WAV는 22,050 Hz 모노 PCM, 0.30~0.46초이며 클리핑 샘플이 없다. 강화·뽑기 버튼은 기존 목재 색감을 유지하고 테두리를 얇게 정리했다. 상단 배경은 안전 영역 위까지 이어지되 조작부는 안전 영역 안에 둔다.

## 검사 과정에서 바로잡은 문제

- 테스트 진입 코드가 이미 열린 게스트 로그인 팝업을 다시 눌러 닫는 문제가 있었다. 현재 팝업 상태를 확인하고 메인 화면 진입을 검증한 뒤 전투 명령을 보낸다. 당시 `StageBackgroundController missing`은 타이틀에서 전투 명령을 보낸 검사 오류였다.
- 두 기기 검사 스크립트를 동시에 실행한 한 차례에 명령 파일 경쟁과 시간 초과가 발생했다. 이후 기기 검사는 순차 실행했다.
- QA HP 조작이 표시용 값을 바꾸던 부분을 실제 피해 경로로 교정한 뒤 자동 보호막·도발을 확인했다.
- 기기/앱이 일시정지되고 오프라인 보상 화면으로 돌아온 사례가 한 번 있었다. 해당 사례의 OS 또는 게임 원인은 확정하지 못했다. 깨우기·복귀 후 진행됐고, 이후 90초 자동 시전과 명시적 백그라운드 복귀에서는 멈춤이 재현되지 않았다. QA 정지 명령에는 자동 해제 기한을 넣었다.
- Windows 파일 매핑 오류 1224로 아이콘/글리프 출력이 실패한 빌드는 임시 파일의 원자적 교체와 불필요한 재작성 생략으로 수정 후 다시 빌드했다. 실패한 빌드를 검증 완료 빌드로 계산하지 않았다.
- 마지막 아틀라스 추가 빌드에서도 EDM 설정 XML의 `File.Replace`가 실패했다. Windows 전용 [MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)의 기존 파일 교체 방식으로 대체 경로를 두고 재빌드에 성공했다. Unity의 현재 API에서 지원하지 않는 `File.Move` 오버로드를 시도한 중간 컴파일 실패도 제외했다. QA 빌더가 예외를 기록한 뒤 다시 던지도록 해 실패를 성공 종료 코드로 보고하지 않게 했다.

## 범위와 남은 확인

한 실제 기기의 화면 비율 변경은 여러 실제 기기 검증을 대신하지 않는다. 장시간 발열, 저사양 실기기, 출시 빌드의 GPU·배터리 프로파일은 이번 짧은 검사에 포함하지 않았다. 90초 표본에서 Unity 할당 메모리는 약 166.0→166.3MB였으며 장기 누수 부재를 보장하지 않는다. 효과음은 신호·음량·동시 재생 경로를 확인했으며 여러 스피커·이어폰에서의 청취 평가는 하지 않았다.

현재 운영 카탈로그와 상세기획서에 확정된 전투·마탑 규칙을 덮어썼다. 스킬 카탈로그는 8개 탭의 수치·툴팁·개화·대상 선정·아트 경로를 검토했고 수식 오류 검색 결과는 0개였다. 기획서 42페이지를 렌더 검수했다. 스킬 카탈로그는 개발자 열람용이며 자동 런타임 임포터로 연결하지 않았다.

추가·변경된 직렬화 참조 GUID 60개가 모두 로컬 Unity 에셋·패키지 메타데이터로 해석됐다. 검증 종료 후 작업 직전 QA 프로필 원본·백업·PlayerPrefs를 바이트 단위로 복원·대조했다. 해상도 1080×2316, 밀도 450, USB 연결 시 화면 유지 설정 원래 값 7로 복원하고 QA 앱을 종료했다. 빌드가 임시 변경한 URP·Android resolver 설정도 되돌리고 게임 버전/code 변경만 유지했다.
